1. About ATE and platform availability

ATE is a local plain-text and code editor with CodeMirror, syntax colors, automatic indentation, search/replace and optional Vim key bindings. It does not run your code. You can edit without creating an account.

Android is distributed as a signed APK from Cuberoot. iOS/iPadOS is currently an invitation-only TestFlight build. The Windows x64 installer is available from Cuberoot. Native Mac TestFlight is available for Intel and Apple silicon. The signed and notarized universal Mac installer is also available from Cuberoot.

2. The editor and Menu

The top row contains ATE, Menu, Close and Save file. The editing area fills the available space. Word and character counts appear at the bottom. Menu holds New, Open, Search / Replace, Go to line, Select all, Copy and Help, plus file and display settings. Tap Done to leave Menu.

With Text buttons, commands display words. With Icons, the same commands use symbols with accessible labels. Full screen hides the main toolbar; Exit full screen restores it.

3. New documents and file names

Choose Menu → New to start over. If the current editor contains text, ATE asks before replacing it. Choose Keep editing to cancel. New does not save the previous document.

Enter the document’s name in Menu. A name without an extension receives .txt when saving. Typical names are shopping.txt, notes.md, page.html and script.py. ATE keeps one active document at a time.

4. Open files safely

Choose Menu → Open. If a document is already open, confirm replacing it only when you no longer need its current in-memory contents. The system file picker can show local storage and supported providers.

ATE imports plain text, including common code, Markdown, CSV, JSON and log files. It does not preserve Word, PDF or rich-text formatting. Files larger than 10 MB and content containing null characters are refused. Cancelling the file picker keeps the current document.

5. Save files

Android/Fire: Save file opens the system file manager. Choose a storage provider/folder, enter a filename, then tap Save. ATE confirms a successful write. Cancel returns to the editor with the draft intact. Save creates a new destination; opening a file does not silently grant permission to overwrite its original.

iPhone/iPad: Save file opens the system share sheet with a text-file copy. Choose Save to Files, choose a folder and complete Save. Check the destination; closing the share sheet alone does not prove a file was saved.

Windows/Mac: Save file or Ctrl+S / Command+S opens the system Save dialog. Choose a folder and filename, then Save. The system asks before replacing an existing file.

On Android and desktop, cancelling or failing Save preserves the editor and recovery draft; Save and close/exit closes only after a successful write. The iOS share flow retains a recovery draft as an additional precaution.

6. Recovery, privacy and backups

ATE automatically stores a recovery draft locally on the same device. Reopening the app can restore that draft. Text size, appearance, button style and editing mode are remembered separately.

There is no ATE cloud synchronization, online account or cross-device draft backup. Clearing app/site data or uninstalling can remove local recovery data. Save independent copies in Files or another chosen destination. Share sheets and file providers may send content to destinations you select.

7. Text size, colors and full screen

Choose Menu → Text size, or A− / A+, from 10 to 54 pt. The default is 27 pt. Direct size entry accepts whole-number points. The setting changes display size only.

Use Light/Dark for the editing theme and Text/Icons for button labels. Choose Full screen for more room, then Exit full screen to restore controls. On-screen keyboards naturally reduce the visible editing area.

Menus, search, syntax messages and C configuration use 12 pt text; headings are at most 14 pt. These control sizes are separate from the document font preference.

8. Language colors and indentation

Choose Plain text, JavaScript/JSX, TypeScript/TSX, JSON, YAML, HTML, CSS, C, Python, SQL or Markdown in Menu. Recognized file extensions select a language automatically; you can change it. Other formats remain editable as plain text.

New lines receive language-aware indentation, using four spaces. Indent and Unindent affect the current line or selected lines. On a hardware keyboard, Tab indents and Shift+Tab unindents. Syntax colors are a reading aid, not a compiler or guarantee that code is correct.

9. Search and replace

  1. Choose Menu → Search / Replace, or Ctrl+F / Command+F.
  2. Enter text in Find. Use Next and Previous; searches wrap through the document.
  3. Enable Match case to distinguish capital letters. By word matches whole words. Leave Regexp off for ordinary text; turn it on only when you intend a regular expression.
  4. Enter replacement text. Replace changes the selected match; Replace all changes all matches. Undo immediately if the result is wrong.
  5. Use the panel’s close button to return to the document.

10. Go to line, select and copy

Menu → Go to line jumps to the line number you enter. Select all selects the whole document. Copy uses the current selection, so select text first. To copy everything, Select all, then reopen Menu and choose Copy.

If clipboard permission is unavailable, ATE displays a Copy text box for manual selection and your device’s Copy command. The system clipboard and Vim’s internal yank register are separate.

12. Optional Vim mode

Choose Menu → Editing → Vim. Vim works best with a hardware keyboard. Standard remains the default. In Normal mode, commands move or change text. Press i to enter Insert mode and type. Press Esc or Ctrl+[ to return to Normal mode. Choose Standard to switch back.

In Normal mode, : opens the visible command line. Enter runs the command; Escape cancels it. This is embedded Vim key-binding support, not a complete Vim installation or a terminal.

For a system clipboard copy to another app, use Menu → Copy. Vim’s y does not by itself copy to the device clipboard.

13. Close, discard and leave the app

Choose Close/Exit or Vim :q for three choices:

  • Keep editing: cancel closing.
  • Save and close: open Save (the share sheet on iOS), then clear the active editor if that action completes. A recovery draft is retained.
  • Close without saving: discard the local recovery draft, clear the active document and its undo history, close panels and dismiss keyboard focus. Existing saved files are kept.

No extra “Editor closed” page is shown. On iPhone/iPad, use the Home gesture to leave ATE; iOS has no supported app-quit control. On Android, closing the document also leaves the app. Android Back closes an open dialog first, or opens the closing choices when the editor is active.

Windows/Mac desktop: Exit, the window close button and Mac Quit use the same Save/Discard/Keep choices. Keep editing returns to the document. Save and exit writes a file before quitting. Exit without saving discards the recovery draft and quits. Files already saved on disk remain.

14. Update and troubleshoot

Android updates: download the latest signed APK from Cuberoot and install over the existing ATE app. Keep the same signing identity; uninstalling first may remove recovery data. iOS updates: open TestFlight and tap Update for ATE.

App missing from TestFlight: check the invitation and the Apple Account used in TestFlight. This is not a public App Store download. No saved file: confirm the selected folder and completed Save action (or share-sheet destination on iOS); ATE does not overwrite the opened file automatically.

Cannot type in Vim: press i, or change Editing to Standard. Cannot find Escape: try Ctrl+[ on a hardware keyboard. Unexpected replacement: Undo, then check Match case, By word and Regexp. Opened file looks wrong: ensure it is plain text, not a PDF/Word document or a binary file.

For the current app version, open Menu → Help. Keep a saved file copy before troubleshooting storage or reinstalling.

Windows: close ATE, download the newest installer from Cuberoot and run it for your account. The Windows installer is unsigned; Windows may show an unknown-publisher warning. Save independent document files before reinstalling. Mac: a universal installer supports both Intel and Apple silicon; open its disk image and copy ATE to Applications. For Mac TestFlight updates, use TestFlight on the Mac. Desktop download availability and versions are shown on the ATE downloads page.

15. Check syntax and C settings

Choose Menu → Check syntax. Results show errors with line/column positions; tap an error to jump to it. Automatic checks can run while typing. JavaScript, TypeScript, JSON, YAML, HTML and CSS are checked locally without executing your program. TypeScript checking covers syntax, not types. Python, SQL and Markdown currently provide editing/highlighting only.

Basic C checking on every platform: iPhone/iPad and Android already include the offline parser. Starting with desktop 0.5.3, Mac and Windows use it by default too. It catches structural syntax errors without any compiler installation or download. It does not resolve headers, expand macros, check types or certify C-standard conformance. It does not compile or run your program.

Optional advanced C checking on Mac/Windows: open Menu → C settings → C checking and choose Advanced: installed Clang. Select an installed Clang if needed, then configure the C standard, project folder, include directories and macros. Advanced mode uses Clang for syntax-only checks. If Clang is missing, return to Basic offline parser to keep checking immediately.

Optional Windows download: after selecting Advanced mode, Get C compiler offers a verified official LLVM-MinGW download with progress and cancellation. It is about 191 MB and requires 3 GB free space. It stays in ATE’s private app folder, without administrator or PATH changes. Basic mode never requires this download. On Mac, an existing compatible Clang can be selected; Apple Command Line Tools are an optional separate installation.
