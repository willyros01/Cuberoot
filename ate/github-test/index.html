Getting started

Tap the editing area and type. Menu contains the controls. Choose a language for syntax colors and automatic indentation. Indent and Unindent work on the current line or selected lines.

Under Buttons, choose Text or Icons. Icons have accessible labels and hover hints. Set Text size from 10 to 54 pt; this changes the document display, not the file contents. Light/Dark changes appearance. Full screen hides the toolbar; Exit full screen restores it.

Search and replace

Menu → Search / Replace opens a panel with Find and Replace fields. Enter the text to find. Next and Previous move between matches; searches wrap around the document. Match case distinguishes capital and lowercase letters. By word matches complete words. Regexp enables regular expressions; leave it off for ordinary searches.

Enter replacement text, then Replace to change the selected match, or Replace all for the document. Undo with Ctrl+Z or ⌘Z if needed. The × button closes the panel. Ctrl+F or ⌘F opens search. Menu → Go to line jumps to a line number.

Select all and copy

Menu → Select all selects the entire document. Reopen Menu and tap Copy to copy the selection to your device clipboard, then paste into another app. To copy only part, select that text first. Copy never removes text. If clipboard access is blocked, a Copy text window lets you select and copy manually.

Optional Vim mode

Menu → Editing → Vim enables Vim key bindings. Standard is the default. Vim is best used with a hardware keyboard. Press i to type (Insert mode), and Esc to return to Normal mode. Switch Editing back to Standard whenever you prefer ordinary editing.

Syntax checking

Menu → Check syntax checks the current document without running it. ATE first detects a recognized filename extension, then scans ambiguous files locally for a likely language. You can override Language in Menu. Detection never renames files; Save preserves extensionless names. Check while typing updates results after a short pause. The footer opens the latest results; tap an issue to jump to its line. An empty list with “check unavailable” does not mean the code is valid.

JavaScript, TypeScript, JSON, YAML, HTML and CSS use bundled offline parsers. TypeScript checking covers syntax only, not types. HTML checking includes inline JavaScript/JSON and CSS; it accepts tags that HTML permits you to omit. CSS checks parsing, not property names or browser support. C uses a bundled basic syntax parser by default on every platform: no compiler download is needed. It checks C structure, but does not resolve headers, expand macros, check types or enforce a particular C standard. Python uses a bundled offline Python 3.13 syntax parser without executing source. SQL checks SQLite syntax without a database. Java uses a bundled Java 21 grammar: it checks syntax only, not imports, types or compilation, and reports the first error it finds. XML checks that tags are well formed; schemas are not validated. TOML checks TOML 1.0 syntax and duplicate keys. INI checks section headers, key = value lines and duplicate keys; INI has no single standard. C++, C#, Go, Rust, PHP, Ruby, Swift, Kotlin, PowerShell and Lua have syntax colours and indentation only; Check syntax reports that no checker is included for them. Markdown lint warns about duplicate headings, unclosed code fences and trailing whitespace. Checks are limited to 512K characters and the first 100 issues. Slow checks stop automatically.

For optional deeper checks in the Mac and Windows desktop apps, choose C settings → C checking → Advanced: installed Clang. On Mac, install Apple Command Line Tools. On Windows, choose Get free C compiler in C settings to optionally download LLVM-MinGW (191 MB, 3 GB free space required). Confirm Download and install to begin. ATE verifies the official download checksum, keeps licenses, and checks standard headers before enabling it. Cancel setup stops the installation; Later keeps editing without a compiler. Setup uses your app data folder with no administrator access or PATH changes, and ATE remembers the installed toolchain after restart. You may also choose an existing compiler. Under C settings, select clang if it is not on PATH, choose the C standard, and optionally choose a source folder, additional include directories and preprocessor macros. Paths and macros are entered one per line; macros use NAME or NAME=value. For a file in a subfolder, choose that file’s folder so quoted relative headers resolve correctly. Header files remain on disk; only the open buffer is checked. Manually selected compiler and project folders last for this app session. The optional ATE-managed Windows compiler is detected again after restart. C checking never builds or runs your program. On iPhone, iPad and the web, About syntax checking explains every included checker and its limits.

Preview

For HTML and Markdown files, Menu → Preview shows the page as it will look, filling the screen. Back to editor returns to your text. Preview is read-only and works offline. Scripts, forms and pop-ups never run, and web links, online pictures and online fonts are not loaded; pictures stored inside the file as data still show. In Markdown, raw HTML is shown as plain text instead of being used. Preview shows the text currently in the editor, including unsaved changes.

Basic and Advanced tools

In Menu → Tools, choose Basic for ordinary text editing or Advanced for coding and projects. Switching changes visible tools and editor presentation, not your text, filenames, edits or project membership. The preference is remembered. New users start in Basic; existing users retain Advanced until they choose otherwise.

Projects

Advanced → Projects creates a project, folders and ordinary text/code files. Select a folder name in the visible tree, then choose Add file or New folder. Add file offers Create file or Choose files. Open project contains saved projects, Create new project, Import/Export ZIP and Manage files. Add files copies chosen files into that destination in ATE storage. Open a file from the tree to edit it in a tab; Save file writes that project copy. Renaming its filename before Save creates a new project copy and keeps the old file. Changes made outside a tab are detected before saving. Export copy uses the platform’s save/export flow without marking the project file saved.

Projects use a JSON project.ateproj manifest and ordinary relative file paths. Mobile and desktop apps keep project files in local app storage. The web version keeps them in this browser’s IndexedDB; clearing browser/site data can remove them, so export ZIP backups. Exported files can be added to other IDEs; ATE does not generate compiler or Xcode project settings. Import/Export project ZIP transfers a complete project; importing creates a new copy. A manifest alone does not contain file contents. ZIP export includes saved members only, so save unsaved project tabs first. Close project closes its tabs and offers Save, Discard or Cancel for unsaved project work; ordinary tabs are kept. Back to editor only dismisses Projects. Manage files → Remove from the list does not delete files. Delete folder previews and deletes that entire subtree after confirmation; save or close its unsaved tabs first. Outside originals and other projects are kept. Up to 200 text files, 100 folders, 10 MB per file and 20 MB total; no project commands are run.

Shell scripts

Shell extensions, startup filenames and interpreter headers such as #!/bin/sh or #!/usr/bin/env bash identify scripts before embedded Python is scanned. Shell highlighting and bundled POSIX/Bash structural checking work offline. Other shell dialects are recognized but not certified by the Bash parser. No shell command or embedded program is executed.

Document tabs

New and Open add tabs on every platform (up to 12). Tap a filename to switch. A dot marks unsaved changes. Each tab keeps its undo history while the app is running. The × closes one tab; unsaved tabs offer Save, Discard or Cancel. Recovery restores text, filenames, language choices and selection after restarting; undo history starts fresh. Recovery is local, has limited storage and is not a saved file. iOS Save creates a copy through the share sheet; confirm that copy in Files before discarding your work. The × closes one tab. On Mac, Windows and Android, Exit retains its whole-app confirmation; Save and exit saves all unsaved tabs, and a cancelled or failed save keeps the app and tabs open. Web Exit clears the editor while keeping saved projects; successful downloads cannot be independently confirmed, so saved recovery is kept.

Files, drafts and exit

Open imports a plain-text file. On the web, Save file downloads a copy. On iOS, it opens a share sheet: choose Save to Files. On Android and Fire tablets, Save opens the system file manager so you can choose a folder and filename. Cancelling keeps your draft. On Windows and Mac, it opens a native Save dialog; choose a destination and confirm replacement if necessary. Web and iOS saves create a copy. Desktop saves can replace a file you select. Check your Downloads or Files app. The editor displays and saves text; it does not execute code.

A recovery draft is saved in this browser on this device. It is not cloud synchronization. Clearing browser data removes it. Save independent file copies for safekeeping.

Exit offers Keep editing, Save and exit, or Exit without saving. Exit without saving clears the browser draft; existing device files stay intact. Save and exit keeps a recovery draft because the browser cannot verify completion of the download. Closing clears the editor and dismisses its panels and keyboard without showing a closing page. On Windows and Mac, Exit closes the application; the window close button also opens the Exit choices. On iPhone and iPad, use the Home gesture to leave the app.
